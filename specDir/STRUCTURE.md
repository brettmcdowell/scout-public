# TerraVision Scout — App Structure

> This document describes the **actual built structure** as of May 2026.

---

## What It Is

TerraVision Scout is a field intelligence web app for farmers. It processes satellite/drone imagery of agricultural fields to detect crop health issues (via NDVI/NDRE analysis), surfaces actionable intelligence, and presents prioritised on-the-ground actions in a format a non-technical farmer can immediately understand.

---

## Product Layers

| Layer | Purpose | MVP status |
|---|---|---|
| **Sensing** | Drone/satellite imagery ingestion, field edge detection | Stub only |
| **Intelligence** | NDVI/NDRE vegetation analysis, zone segmentation, scan comparison | Built — synthetic data |
| **Visualisation** | Heatmap overlay rendering over field images | Built — CSS radial gradients over PNG images |
| **Action** | Prioritised action dashboard with measurable upside metrics | Built |
| **Onboarding** | Entry flow: postcode → imagery → field selection | Route exists, not built |

## Key Files Explained

### `src/components/layout/AppSidebar.tsx`

Fixed 56 px sidebar. Three nav items (Overview, Intelligence, Action). Each item is a TanStack `<Link>` centred with `justify-center`. Active state: `bg-green-50 border-l-[3px] border-green-600`. Uses native `title` attribute for tooltips — **not** Flowbite `<Tooltip>` which breaks centering. Avatar at bottom opens a Flowbite `<Modal>` with disabled Settings/Log Out.

### `src/routes/overview.tsx`

Self-contained page — no separate layer component. Contains:
- `STATS` array for the 4-card stat strip
- `FIELDS` array with `posX`/`posY` absolute coordinates for label placement on `all.png`
- `FIELD_MOCK` record of per-field NDVI/soil data shown in the stats slide-in panel
- `FarmOverviewTab` — handles zoom animation state (`selected`, `animIn`)
- `RecentScansTab` — custom accordion
- `FarmSummaryTab` — key-value rows

### `src/layers/intelligence/IntelligencePage.tsx`

All intelligence UI in one file. Key exports/functions:
- `FIELD_DATA` — synthetic NDVI zone data per field per scan date
- `ndviColor(v)` / `ndreColor(v)` — maps 0–1 value to hex colour
- `ndreAvgFromZones(zones)` — derives NDRE average from NDVI zone data
- `zoneLabel(cx, cy)` — derives compass label (NW/N/NE/W/Centre/E/SW/S/SE)
- `generateInsights(field, scanAId, scanBId)` — returns 3 insight bullets
- `FieldHeatmapView` — renders one field image with heatmap + date selector + scale bar
- `IntelligenceInsights` — right panel with 5 always-expanded cards
- `IntelligencePage` — page root, manages state (selectedField, scanA, scanB, layer)

### `src/layers/action/ActionPage.tsx`

All action UI in one file. Key structures:
- `TOP_ACTIONS` — array of 4 action objects (High × 2, Medium × 2)
- `PRIORITY_CONFIG` — dot/pill/bar Tailwind classes per priority level
- `CATEGORY_CONFIG` — icon component + colour classes per category
- `ActionPage` — renders stat strip (3 stats + download CTA) + 2×2 grid

## Data Model (Synthetic MVP)

All data is hardcoded synthetic data — there is no live API call from the frontend in the current build. The FastAPI backend has a `/api/hello` health endpoint and an intelligence stub.

### Field record
```ts
type Zone = { cx: number; cy: number; rx: number; ry: number; v: number }
// cx/cy: centre position as % of image (0–100)
// rx/ry: semi-axis radii as % of image
// v: NDVI value 0–1

type FieldScanData = { zones: Zone[]; avg: number; stressed: number }
// avg: field-level mean NDVI
// stressed: % of area with NDVI < 0.4
```

### Scan dates

## Tech Configuration

### Tailwind v4 setup

Tailwind v4 uses a CSS-first config — no `tailwind.config.js`. Everything lives in `index.css`:
```css
@import "tailwindcss";
@plugin "flowbite/plugin";
@source "../node_modules/flowbite-react/dist/esm/**/*.js";
```

### TanStack Router

Vite plugin auto-generates `routeTree.gen.ts` on every `npm run dev` from files in `src/routes/`. Route files export a `Route` constant created with `createFileRoute('/path')({ component: ... })`.

### FastAPI backend

```bash
cd server && source .venv/bin/activate && fastapi dev main.py
# Runs on http://localhost:8000
# CORS allowed origin: http://localhost:5173
```

```bash
cd client && npm run dev
# Runs on http://localhost:5173
```

## Design Decisions

- **No Leaflet / no map library** — field imagery is real PNG files. Heatmaps are CSS radial gradients positioned absolutely over the images. This avoids API keys, tile loading, and Leaflet CSS conflicts.
- **No app header** — page identity communicated by the small `text-sm font-semibold text-gray-400` label at top of each page's content area.
- **Fixed sidebar, never collapses** — simpler layout contract; all pages assume `calc(100vw - 56px)` available width.
- **Native `<select>` over Flowbite `<Select>`** where values are very short (1–6) or where the element lives on a dark image background — Flowbite's wrapper constrains width and cannot be styled with `colorScheme: dark`.
- **Native `title` over Flowbite `<Tooltip>` on nav items** — Flowbite Tooltip renders `display: inline-block` which collapses the Link width and breaks `justify-center` icon alignment.
- **Synthetic heatmap, no backend call** — NDVI/NDRE zone data is a hardcoded `FIELD_DATA` constant. The visual heatmap uses CSS `radial-gradient` blobs, not a server-generated image, so the Intelligence page works without a running backend.
- **Two-step zoom animation** — field zoom uses a mount-then-transition pattern: element mounts at `scale(0.15)`, a 20 ms `setTimeout` then sets `animIn = true` to trigger the CSS transition to `scale(1)`. This ensures the element exists in the DOM before the transition fires.
- **Right panel never scrolls** — Intelligence right panel is sized to fit all 5 sections on screen. Content density is tuned so no `overflow-y-auto` is needed.
- **Action page shows only top 4 actions** — Low-priority actions are intentionally excluded from the 2×2 grid to keep the dashboard scannable for a non-technical farmer.
